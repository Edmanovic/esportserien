# Vault Format V1

Vault Format V1 is a server-safe schema. It contains encrypted payloads, key slots, revisions, timestamps, and conflict records. It does not contain plaintext item fields, TOTP seeds, passwords, secure notes, or vault data-encryption keys.

## Serialization

MVP schemas use strict Serde-compatible JSON for protocol boundaries. Deterministic authenticated data is generated by `crypto-core` for encryption context. Future binary serialization must preserve field order rules, reject unknown downgrade versions, and receive an ADR before adoption.

## Objects

- `VaultEnvelope`: schema version, metadata, encrypted header, key slots.
- `VaultItem`: item UUID, vault UUID, encrypted payload, attachment references, revision fields, audit timestamps.
- `EncryptedPayload`: envelope version, nonce, ciphertext, authenticated context reference.
- `KeySlot`: encrypted vault key for a device, share target, or recovery method.
- `VaultMetadata`: server-visible vault metadata only.

## Migration Rules

- Clients must reject unknown lower versions that indicate rollback or downgrade.
- Clients may preserve unknown higher-version records but must not decrypt them until upgraded.
- Migrations are client-side because only clients can decrypt private vault data.
- Migration records include source version, target version, client build, and timestamp.
